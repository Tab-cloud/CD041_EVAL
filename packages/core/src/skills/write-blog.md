# 博客写作与发布

## 识别交付目标

1. 用户只要求撰写或润色时，交付完整文章；不要创建 Web 草稿或公开发布。
2. 用户要求保存为草稿时，完成内容校验后调用 `community_blog_create_draft`。
3. 用户明确要求“发布、公开发布、写完并发布”时，先创建草稿；仅在草稿成功并返回 `draftId` 后调用 `community_blog_publish`。
4. 用户要求发布论坛帖子时，不要把它伪装成博客；改用论坛工具及对应权限流程。

## 调研与成文

1. 优先读取用户指定的文件、原理图、数据手册、代码和项目资料；需要时使用联网检索补充公开资料。
2. 把已验证事实、合理推断和未知事项明确分开。不得虚构测试、项目周期、个人经历、性能数据、兼容性或量产结论。
3. 围绕目标读者组织标题、摘要、引言、分节正文、操作建议、风险边界和结论。技术内容应包含必要的型号、版本、前提和可复核依据。
4. 发布前移除本地绝对路径、内部账号、密钥、令牌、未公开项目名称及其他不应公开的信息。不得大段复制受版权保护的来源。
5. 校验标题与正文一致、术语统一、引用可追溯、Markdown 结构完整；不要把未完成事项描述为已验证结果。

## Eval Web 博客工具合同

创建草稿只允许传入：

- `title`：4 至 140 个字符。
- `excerpt`：10 至 320 个字符。
- `body`：40 至 50000 个字符，使用 Markdown。

调用示意：

```text
community_blog_create_draft({ title, excerpt, body })
```

博客草稿没有 `category` 参数。`category` 仅用于 `community_forum_create_topic`，不得传给博客工具，也不得把参数对象序列化成字符串。

更新草稿只允许传入 `draftId` 以及确需修改的 `title`、`excerpt`、`body`。公开发布只允许传入：

```text
community_blog_publish({ draftId })
```

## 授权与失败处理

1. Skill 不授予权限。所有工具仍受当前执行范围、Eval 本地社区策略、通用网络策略、Web 用户授权、设备 Scope、账号角色、限流和内容校验约束。
2. “允许”模式可继续执行；“询问”模式必须等待用户在审批界面决定；“拒绝”模式不得用脚本、论坛工具或其他网络路径绕过。
3. 草稿创建失败时不得调用发布工具。根据结构化错误修正合法参数后，可重试修正后的调用；不得原样重复失败输入。
4. 博客发布失败时保留已经创建的草稿，向用户说明草稿状态与真实失败原因。不得擅自降级为论坛帖子或要求用户执行无关命令。
5. 只有工具返回成功状态、博客或草稿标识以及可用链接时，才声明创建或发布成功；否则准确说明尚未完成。

## 交付检查

- 只写：返回完整文章，并说明未向 Web 提交。
- 草稿：返回标题、草稿标识、草稿状态和可用链接。
- 发布：返回标题、发布标识、公开状态和可用链接。
- 受阻：保留已完成文章或草稿，列出唯一真实阻塞条件，不把内部恢复策略冒充用户选项。
