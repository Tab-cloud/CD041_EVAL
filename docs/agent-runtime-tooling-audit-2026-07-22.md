# Agent 运行时与工具完整性审查（2026-07-22）

> **历史文档说明（2026-08-26）：** 本文是 2026-07-22 的审计与修复记录，属于历史过程文档，
> 不作为当前实现的规范来源。当前执行架构以
> [`agent-execution-loop-architecture.md`](./agent-execution-loop-architecture.md)（2026-08-09 复核）为准，
> 功能清单见 [`backend-features.md`](./backend-features.md)。

## 结论

Eval 暴露的“任务执行一段后停止，必须由用户输入请继续；右侧任务仍显示执行中”不是某个业务工具的点状故障，而是执行控制面的架构缺口：模型循环、子 Agent、任务调度器和前端 Context 面板分别维护了局部状态，但缺少完整的运行时闭环和统一终态投影。

本次修复不修改 ECG 示例工程，修复对象是 `embedded-agent` 自身的 Agent/工具运行架构。

## 已确认的根因

1. `AgentLoop` 只在单个执行段内循环。达到步数或停滞边界后进入总结并返回，`TaskScheduler` 只记录 `interrupted`，不会继续调度同一目标。
2. 是否建立待办与验收条件依赖模型主动调用 `todowrite`。部分角色没有声明该工具；模型若直接结束且待办为空，运行时可能把操作型请求误判为完成。
3. `task` 子 Agent 只把文本汇总给父 Agent。子 Agent 的 `execution-stopped` / `execution-blocked` 语义被丢弃，只要存在阶段性文本就可能被当成成功结果。
4. 服务端执行快照、任务状态和前端本地待办不是同一终态投影。中断快照仍可保留 `in_progress`；旧的中断执行又会长期压过较新的完成执行，造成 Context 面板显示陈旧状态。
5. 客户端硬超时曾短于后端根执行窗口及模型收尾时间，可能提前断开仍在运行的任务展示通道。
6. Agent 声明的工具名称只在实际调用时才暴露配置错误，启动阶段没有完整性校验。
7. 推理工具事务的回放策略依赖 `DeepSeek` 名称匹配；模型别名、代理或其他兼容供应商也要求 `reasoning_content` 时，会在已执行一部分任务后返回 HTTP 400。
8. 执行控制器曾用工具名称子串推断“变更/验证”语义，`todowrite` 因名称包含 `write` 被误判为工作区写入，制造无法关闭的 `*` 验证缺口，使任务即使已有证据仍反复续段并停在 `finalizing`。

## 架构修复

### 1. 运行时拥有目标与验收门

操作型请求由运行时建立根目标和验收条件。即使模型没有调用 `todowrite`，也不能仅凭一次自然语言停止输出宣告完成。`todowrite` 作为控制面工具由运行时向所有角色注入，不再依赖每个专业角色重复声明。

### 2. 有界自动续段

步数耗尽或停滞只结束当前执行段，不等价于结束用户目标。只要仍有可执行待办或验证缺口，运行时就在同一消息账本、证据账本和绝对截止时间内自动开启下一段：

`理解目标 → 拆分/接管待办 → 执行 → 工具反馈 → 调整策略 → 验证 → 验收`

续段有最大次数并继承根截止时间；时间到期、用户取消、权限/硬件/用户决策等真实外部条件仍会形成明确终态。这是基于奖励/失败反馈的执行策略，不是在线训练模型参数。

### 3. 子 Agent 使用结构化终态

子 Agent 的中断、阻塞、超时和失败会作为失败结果回传父 Agent，并携带阶段性成果和诊断。文本存在不再代表子任务成功。通用协调角色获得受深度限制的 `task` 能力，内部可以按职责自动分配，而无需向用户暴露角色切换。

后续真实测试又确认“所有子 Agent 直接继承根绝对截止时间”仍不充分：父 Agent 同步等待时，单个子任务可以耗尽整棵执行树，导致返回的“父 Agent 接管”建议已无预算可执行。现在根任务是预算所有者，子 Agent 只能领取有限租约，并强制保留父任务恢复与验收窗口。租约到期是可恢复反馈，不是根任务终止。

### 4. 单一终态投影

服务端 `execution_runs` 是待办状态的事实源。任务进入 `interrupted`、`failed`、`cancelled` 时，`in_progress` 待办统一落为 `paused`；进入 `blocked` 时落为 `blocked`。任务状态恢复接口同时返回该任务的执行快照，前端重连和会话恢复均以它覆盖本地缓存。

Context 面板优先展示真正活跃的执行；没有活跃执行时展示最新执行，旧中断任务不再永久遮蔽更新的已完成任务。

### 5. 启动期能力图审计

运行时启动时检查：

- Agent 引用的工具是否已注册；
- 控制面工具是否存在；
- 声明了委派能力的角色是否被权限规则反向拒绝；
- 是否至少存在一个同时具备工作区写入、进程执行和任务委派能力的协调角色。

错误会阻止带缺陷的运行时启动，非致命配置问题会产生内部警告，不交给最终用户或 LLM 自行发现。

### 6. 按协议能力回放推理事务

推理事务回放不再通过供应商名称或模型 ID 猜测。OpenAI-compatible 协议路径按模型声明的 `reasoning` 能力采用保守回放：只有带有对应模型原始推理内容的工具事务才按原生协议重放，其余历史事务折叠为语义证据，避免 `reasoning_content` 缺失导致整条任务链在中途失败。

模型 ID 现在只作为发往服务端的请求值和日志标识，不参与协议、Vision 消息格式、token 参数或成本策略分支。协议由显式 provider/capability 决定；成本在没有外部价格配置时使用模型无关基线，避免把过期模型价格写死在运行时。

### 7. 工具进展语义契约

安全能力与任务进展不再混用。每个工具必须显式声明自己在执行闭环中的角色：`control`、`inspection`、`mutation`、`verification`、`delegation` 或 `dynamic`，以及目标参数和验证范围。执行控制器只消费这份结构化语义，不再按工具名称猜测。

因此 `todowrite` 只更新控制面，不产生文件验证债务；`write/edit` 产生目标明确的变更债务；`read` 只能验证对应路径；`compile` 可作为全局验证；`bash` 和未知 MCP 工具按动态且保守的规则处理。工具管理界面同步展示该进展角色，便于审计注册错误。

### 8. 统一 Run 谱系与会话 Actor

会话、执行实例和权限上下文不再复用一个字符串承担三种身份：

- `sessionId` 表示用户对话和上下文归属；
- `runId` 表示一次可追踪执行；
- `parentRunId` / `runType` 表示根任务、子 Agent、工作流节点之间的谱系；
- `checkpointKey` 隔离各执行实例的恢复点；
- `permissionContextId` 显式继承安全上下文。

子 Agent 和工作流节点继续归属于原会话，但其工具流、角色和任务谱系只写内部审计记录，不进入公共消息与 SSE；必要审批经过主 Agent 边界净化后展示。它们拥有独立 Run、检查点和工具审计记录。调度器以 conversation lane 串行化同一会话内互不相关的任务，同一工作流 owner 的独立 DAG 节点可以受控并行，避免多个根任务并发修改同一上下文。

根聊天、子 Agent 和工作流节点共同调用一个终态分类器。`AgentLoop` 返回、产生文本或子任务返回摘要都不再是完成证据；只有持久化执行快照进入 `completed` 才能对上层报告成功。

### 9. 审批是持久化的应用级中断

审批请求先写入数据库，再进入内存等待队列；审批结果先持久化，再唤醒执行协程。数据库失败时不会发布不可恢复请求，也不会提前丢失仍在等待的协程。

等待审批的任务从计算槽挂起，但继续占有会话 lane，其他会话可以使用释放的并发容量；批准后原任务必须重新取得调度权，才能继续产生副作用。前端维护审批数组而不是单个槽位，并持续读取全局审批队列。后台工作流、非当前会话和断开 SSE 的任务所发起的审批都会立即展示、聚焦，并标明来源会话。

### 10. SSE 可恢复事件协议

运行时协议版本统一生成事件类型。关键事件在发送前写入 `run_events`，按 Run 分配单调递增序号，并作为 SSE `id` 发出。客户端记录最后序号；连接中断后同时读取任务事实快照和 `after=<last-id>` 增量事件，重放断线期间的审批、执行状态、工具审计和上下文压缩状态。

客户端生成的 `requestId` 同时持久化到任务记录。即使连接在第一条携带 `taskId` 的 SSE 事件到达前中断，客户端仍可通过 `requestId` 找回任务和后端分配的会话，不会留下只能在后台运行、前端无法附着的孤儿任务。

事实状态和通知日志职责分离：`execution_runs` / `task_runs` 决定终态，事件日志用于无缝恢复 UI；事件日志暂时故障不会吞掉实时通知，也不能把未完成任务改成完成。

### 11. 配置驱动的模型与工具能力

运行时不再内置供应商 modelId 或默认模型。模型目录完全来自用户配置；能力覆盖是路由硬约束，优先级和成本只在完整覆盖所需能力的候选中排序。不存在合格模型时明确失败，不允许用高优先级但缺能力的模型冒充。

Agent 选择会按当前执行范围和系统工具策略检查真实可见工具。工具授权检查所有声明目标和常用路径字段，数组路径逐项校验，命令白名单只检查明确的 `command`。纯代码生成器不能再声明虚假的工作区写入或完成证据；例如 `lvgl_gen` 明确返回 scaffold，后续必须经过写入、实现和编译验证。

### 12. 自动输出预算与长结果保真

`maxOutputTokens` 不再作为前端用户配置项。运行时根据模型声明的总上下文窗口自动分配输入/输出预算，配置归一化时忽略旧文件中的手工输出值；策略不依赖供应商名称或 modelId。

模型流的 `finish_reason=length` 和 Anthropic `stop_reason=max_tokens` 不再被当成正常完成。普通回复和工具内模型分析都会自动发起有界续写，并要求从中止位置继续，避免重复已有段落。

工具结果仍使用通用的有界头尾信封，但原理图和数据手册属于结构化证据输出，允许在更大的专用边界内完整进入下一轮推理。前端工具日志只显示“完整分析已送入后续审查上下文”，不再用“长文本 N 字符”造成已经丢失正文的误解。

原理图独立复核由完成门改为非阻塞审查信号：`CONFIRMED / CONFLICT / INSUFFICIENT` 分别映射为可信度和补证建议。冲突或证据不足时继续输出可见事实、冲突双方和待核项，不中止整份硬件—程序对应关系审查。

## 安全边界

- 自动续段不延长根任务的绝对时间上限。
- 用户显式取消立即终止执行树。
- 审批、硬件和用户决策仍是合法阻塞条件。
- 子 Agent 继承根权限上下文和预算策略，但不能消耗父任务恢复预留。
- 连续无进展不会无限循环；达到有界续段次数后保存进度并进入中断终态。
