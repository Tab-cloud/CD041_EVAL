# LLM 优先的非阻塞执行设计

## 目标

运行时负责守住用户授权和系统安全边界，同时把工具、路由、计划、委派和工作流中的失败保存为结构化证据，交回主 LLM 继续决策。除真实外部约束外，运行时不得把一次失败升级为根任务终止。

## 必须强制执行的边界

- 用户选择的执行范围、工具策略、写入路径白名单和命令白名单。
- 需要确认的操作必须等待用户批准；拒绝、取消和超时不得被其他工具绕过。
- 用户取消、进程退出、资源写冲突、子任务租约和并发写入互斥。
- 工作区回滚失败后的安全隔离，以及不可伪造的持久化审计记录。
- 模型配额、凭据缺失、网络不可达、外部硬件和其他真实不可用资源。

## 仅作为建议的信息

- 自动路由和能力匹配结果。
- 已提交计划、计划节点和阶段提示。
- 工具诊断给出的恢复步骤、候选工具和恢复预算。
- 待办、验收证据差距、工作流重试和子 Agent 失败。

这些信息可以影响提示词和审计，但不能缩减已授权工具面、强制指定工具、禁止重新规划，或在主 LLM 仍有合法替代方案时终止根任务。

## 失败循环

1. 工具或子 Agent 返回结构化失败：摘要、指纹、证据和建议动作。
2. 运行时记录失败，并禁止原样重复相同工具和相同输入。
3. 下一轮仍向主 LLM 暴露用户当前范围内的完整授权工具面。
4. 主 LLM 可改参数、改路径、改方案、直接执行、改选 Agent、重新规划或询问用户。
5. 步数和时间窗口只形成可续接的执行段；根目标仍有可执行工作时自动续接。

## 计划与工作流

- 计划保留不可变身份和节点合同，用于审计显式计划引用。
- 计划存在时，主 LLM 仍可执行未绑定计划引用的恢复操作或提交新的委派图。
- 工作流默认继续独立分支并进行一次带失败证据的自适应重试。
- 用户显式配置的 `fail-fast` 和重试次数保持有效。

## 完成语义

普通模型在没有待处理原生工具调用时可以直接交付。待办、恢复建议和证据差距继续持久化用于诊断，但不制造额外的架构完成门。只有用户等待、用户取消或真实外部约束可以形成阻塞状态。
